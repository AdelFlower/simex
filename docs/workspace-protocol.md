# SimEX workspace v1：方法、边界与来源

本实现交付 Preparation → Stage1 → Stage2 → 冻结评估的运行框架。离线验收不等于
自主学习或 MuJoCo → Isaac 迁移成功。正式实验必须使用独立目录、显式请求上限和冻结的公开输入。

## 方法对应

| 方法 | 输入能力 | 目标适应 | 评分用途 |
|---|---|---|---|
| `direct_cap` | Preparation 后的通用感知与运动原语 | 无 | 完整自主流程的基线 |
| `stage1_transfer` | 独立源域学习并选拔的 Stage1 库 | 无 | 学习能力直接迁移基线 |
| `simex` | 同一 Stage1 库 | 每任务五轮代码级源模型校准和能力修复 | 完整自主流程 |
| `skill_transfer` | 人工提供的 `direct_plate` | 无 | 独立人工能力诊断 |
| `skill_stage2` | 同一人工能力库 | 同一套 Stage2 实现 | 人工能力的 Stage2 诊断 |

两个入口共享 `simex/stage2.py` 的校准、四候选筛选和冻结评估。人工入口不生成
`discovery.json`，也不进入自主 Stage1 初始化。旧协议的命令和报告适配保留；旧实验
不得用新协议恢复，不得和新统计合并。

## 与论文的对应和差异

依据仓库中的 `2609.38982v1.pdf` §2.1–2.4、Appendix A 和 Table 2。

| 项目 | 当前实现 | 归属 |
|---|---|---|
| 持久能力 | `toolbox.py`、`skill.md` | SimEX 方法 |
| 执行策略 | 每次新的一次性、无工具文本请求；固定回放使用原脚本 | SimEX 方法 |
| Stage1 群体与周期 | 4 成员 × 20 周期 | Table 2 |
| 探测、聚焦、能力回放 | 28、10、5 场景 | 28 和 5 是论文区间内的固定选择 |
| Stage2 | 每任务 5 轮，4 修复，5 共享场景，当前库也筛选 | Table 2 |
| 独立重复与评估 | 5 次重复，各方法每任务 5 次评估 | Table 2；当前任务子集共 300 目标槽位 |
| 模型 | GPT-6 Astra；Preparation/Stage1 max，Stage2/评估 medium | 与论文所用模型不同 |
| 机器人和任务 | Panda；`far_plate`、`far_to_near`、`shifted_single` | 与论文机器人、完整任务集合不同 |
| 模拟器 | MuJoCo 源域、Isaac Sim 目标域；640×480 RGBD | 本仓库 sim2sim 设置 |
| 源模型修改额度 | 每轮至多 3 次，最后一次有效回放后仍判断对齐 | 本地工程上限 |
| Stage1 资源上限 | 每周期 40 个研究推理请求、10 批候选测试 | 本地工程上限，不冒充 Table 2 参数 |
| 源域选拔 | 所有成员冻结后，以完整放置源任务评估，研究代理给理由 | 本地选拔场景数量为 `selection_trials` |
| 早期能力库为空 | 回放批用探测任务补足，并标为未验证覆盖项 | 不制造历史成功 |
| 重试 | 最多 5 次，5/15/30/60/60 秒；全部计费，不切模型 | 本地恢复策略 |
| 源模型扩展边界 | XML 数值建模、命令时长、逐步控制；固定拓扑与机器人接口 | 比任意物理程序编辑更严格的工程限制 |

源模型拟合允许存在歧义。研究代理确认行为对齐，只意味着它认为相关观测相符，
不代表真实接触参数被识别，也不代表候选已经可迁移。报告必须同时给出匹配行为、
剩余差异和源域筛选依据。两边都失败不构成对齐证据。

## 持久会话与权限

每次重复独立初始化；每个 Stage1 成员和每个 Stage2 任务各有自己的 CLI 会话 ID。
修复候选使用独立工作区，从同一父库开始，不继承其他候选的隐藏会话。成员在周期边界
只交换冻结的摘要。选拔代理单独建会话。冻结评估只创建无历史的 `PolicyWriter`。

研究容器固定 Codex CLI 0.162.1，`--network none`、只读根文件系统、无 GPU、无宿主
凭据。只挂载该会话的工作区、公共证据、手写 RobotAPI 手册和受控 Unix 套接字。
Preparation 另包含经过哈希检查的允许源资产副本。校准只允许 `model.py` 提交，能力
阶段只允许 `toolbox.py`、`skill.md`；宿主再次验证提交内容。仿真在宿主独立进程运行，
物理执行通过全局文件锁串行调度。

研究者可以读完整的策略代码、公开轨迹、RGBD、图片和视频。索引只负责定位文件，
不引入额外摘要模型。CLI 自身的上下文压缩请求会进入同一预算。

受控操作为 `status / submit / test / commit / finish`，均绑定阶段、输入哈希和 ID。
提交保存文件快照与 diff。测试结果绑定精确版本，未测试草稿不能 commit。相同 ID
重复调用返回既有结果；中断执行不会因为换一个提交 ID 就被自动重跑。

`skill.md` 组织技能接口、前后置条件、停止条件、失败现象、恢复方式、证据 ID 和验证
范围；完整轨迹和研究笔记留在工作区，不进入冻结策略输入。能力库记录首次成功、
最近成功、当前结果和具体代码版本；一次失败不会抹掉历史成功。

## 预算、恢复和验收

宿主网关是唯一模型出口。每个向服务实际发送的请求都单独记账，包括重试、工具调用
后的继续推理和压缩。原子预算预留在发送前持久化；若恰在预留与发送之间崩溃，该
未确认请求保守保留计数，不退款。记录有效回复、失败分类及每请求 token 用量，
不把 CLI 的累计 turn 用量重复相加。请求上限没有默认值，也不继承旧实验预算。

认证可选 `codex_chatgpt`（默认配置）或 `api_key`。前者由宿主读取现有 Codex 文件登录，
向固定的 ChatGPT Codex 上游发送凭据；容器只持有会话网关令牌。过期登录由固定 CLI 的
`account/read(refreshToken=true)` 刷新，不在研究容器实现登录，也不将登录状态复制到工作区。
OAuth 刷新不是模型推理；失败的刷新不消耗推理请求额度，实际发送的模型请求均计数。
认证拒绝会明确报错，重新登录后按运行台账恢复。适配依据
[官方 ChatGPT 网关文档](https://learn.chatgpt.com/docs/enterprise/sign-in-with-chatgpt-through-a-gateway)
及本机 CLI 0.162.1 导出的认证协议；容器隔离边界保持不变。

网络、明确容量不足、可重试服务故障最多恢复五次；非法策略、模型代码错误不作为
服务故障重试。网关缓冲完整响应后才向 CLI 交付，防止断流中的部分工具调用被重复
执行。恢复使用明确的 `codex exec resume SESSION_ID`，先核对操作台账和输入哈希。
已开始但没有持久结果的物理执行保持中断；保存结果后、提交台账前崩溃可只补记提交。

`released_placement_v1` 是正式判据：抬升、完整入箱、红盘留外，以及开爪、撤手、
分离和最终稳定。动作数、持物外观、运输阶段诊断不能替代它。缺少必要视频或轨迹
的真实执行会保留原结果并标记证据错误；不计作成功，也不自动重跑。

完成目标槽位表示流程结束。适应后的完整目标成功才是目标能力证据；优于配对的
直接迁移基线才是本轮观察到改善。单轮研究不声明统计显著或论文成功率已复现。
基线已全成功时明确报告没有测出增益的空间，不临时加难。

## 借鉴来源

`ref/EmbodiedEvo` 保持只读，没有运行时 import，也没有复制其机器人控制器。
借鉴点来自其 `orchestrator/session.py`、`session_runner.py`、`agent_recovery.py`、
`replay.py`、`files.py` 和容器启动设计：持久会话、公共证据工作区、Skills/Lessons、
执行前代码快照、RPC 留档、冻结后测试、基于会话 ID 的有限恢复。

没有采用该框架在同一目标 episode 中持续改程序的策略方式；SimEX 策略仍是一轮文本。
也没有采用把宿主认证文件挂入容器、或用普通 bridge 网络冒充网络过滤的做法。
本地参考导出未提供可直接依赖的统一项目许可证，因此采用独立实现，不把参考目录
打包或作为运行依赖。

CLI 命令行为以安装的 0.162.1 `exec --help`、`exec resume --help` 及
[官方非交互接口](https://learn.chatgpt.com/docs/non-interactive-mode) 为依据。
